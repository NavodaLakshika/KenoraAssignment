# Workshop Registration Service

A full-stack, enterprise-grade Workshop Registration Service built with **React + Vite**, **ASP.NET Core Web API (.NET 8)**, and **Microsoft SQL Server**.

Designed for high reliability under concurrent load, strictly enforcing capacity limits with SQL Server row-level locking so workshops are never overbooked, even under simultaneous high-frequency registrations.

## Database Connection & SQL Server (SSMS)

### Connecting via SQL Server Management Studio (SSMS)
When connecting to SQL Server in SSMS:
- **Server type**: `Database Engine`
- **Server Name**: `.` or `localhost` or `DESKTOP-L3SG4M5`
- **Authentication**: `Windows Authentication`
- **User name**: `DESKTOP-L3SG4M5\Administrator`
- **Database**: `WorkshopRegistrationDb`

The database schema and seed data are automatically generated by the backend on first run via `DbInitializer.cs`. You can also execute `database/seed.sql` directly in SSMS.

## Getting Started

### 1. Prerequisites
- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
- [Node.js](https://nodejs.org/) (v18+)
- Microsoft SQL Server (LocalDB, Express, or Developer instance)

### 2. Start the Backend API
```powershell
cd backend/WorkshopRegistration.Api
dotnet run
```
The API starts at `http://localhost:5012` with Swagger available at `http://localhost:5012/swagger`.

### 3. Start the Frontend
```powershell
cd frontend
npm install
npm run dev
```
Open `http://localhost:5173` in your browser.

## Concurrency Control & Overbooking Protection

To prevent race conditions when multiple staff members register attendees for the final seat simultaneously, `RegistrationService` uses a dedicated SQL Server update transaction with lock hints:

```csharp
await using var transaction = await _db.Database.BeginTransactionAsync(IsolationLevel.ReadCommitted);

var workshop = await _db.Workshops
    .FromSqlInterpolated($"SELECT * FROM Workshops WITH (UPDLOCK, ROWLOCK, HOLDLOCK) WHERE Id = {dto.WorkshopId}")
    .SingleOrDefaultAsync();

var activeCount = await _db.Registrations
    .CountAsync(r => r.WorkshopId == dto.WorkshopId && r.Status == "Active");

if (activeCount >= workshop.Capacity)
{
    await transaction.RollbackAsync();
    return new RegistrationResult { Success = false, StatusCode = 409, Message = "This workshop is full." };
}

// Seat is guaranteed; insert registration and commit
```

### Running the Concurrency Test
A multi-threaded benchmark sends 10 simultaneous asynchronous HTTP requests trying to claim the 1 remaining seat of workshop `WS-CAP1`:

```powershell
dotnet run --project tests/ConcurrencyTester.csproj
```

**Results:**
- Exactly 1 request receives `201 Created`
- Exactly 9 requests receive `409 Conflict (Capacity reached)`
- Active registrations strictly equal capacity with **zero overbooking**.

## Key Features & Quality Measures

- **Dependency Injection**: Clear inversion of control via `IAuthService`, `IWorkshopService`, `IRegistrationService`, and `IUserService`.
- **Structured Logging**: `ILogger<T>` configured across all services and controllers.
- **Robust Exception Handling**: Controller and service-level `try-catch` with rollback safeguards plus a global ASP.NET Core exception middleware.
- **Non-Destructive Cancellation**: Cancelled registrations update status and record `CancelledBy` and `CancelledAt` without deleting data.
- **Modern React Interface**: Glassmorphism aesthetic, responsive cards, real-time seat gauges, status chips, and toast notifications.
